# Plan: Cambiar imagen de fondo del login

## Goal
Permitir que el administrador cambie la imagen de fondo de la página de login sin tocar código, simplemente reemplazando un archivo.

## Current context / assumptions

- Login vive en `modulos/sesion/iniciar_sesion.php` (línea 45)
- La imagen se carga vía CSS en la clase `.auth-one-bg`:
  `background-image: url(../images/auth-one-bg.jpg)` (en `plantilla/assets/css/app.min.css`)
- Existe también `plantilla/assets/images/bg-auth.jpg` (alternativa del tema)
- El overlay actual usa un gradiente oscuro semi-transparente (`.auth-one-bg .bg-overlay`)
- La imagen actual pesa ~240 KB (aceptable para login)
- El usuario quiere poder cambiarla "a voluntad" = sin editar CSS ni recompilar nada

## Architecture / proposed approach
1. Mover la referencia de la imagen del CSS minificado al `custom.min.css` (ya existe y se usa para overrides del tema), usando una ruta relativa al root del proyecto (`img/`) para que sea más intuitivo dónde poner la nueva imagen.
2. Crear un directorio `img/login/` donde el administrador pueda subir su imagen.
3. La ruta será configurable desde un solo lugar (variable PHP en `configuracion.php` o un define en el mismo `iniciar_sesion.php`).

## Step-by-step tasks

### 1. Crear carpeta y copiar imagen actual como placeholder
```bash
mkdir -p "C:/xampp/htdocs/voley/img/login"
cp "C:/xampp/htdocs/voley/plantilla/assets/images/auth-one-bg.jpg" "C:/xampp/htdocs/voley/img/login/bg-default.jpg"
```

### 2. Agregar constante de configuración en `configuracion.php`
**Archivo:** `C:/xampp/htdocs/voley/configuracion.php`

Buscar un buen lugar (junto a otras define/constantes) y agregar:
```php
// Imagen de fondo del login (ruta relativa al root del proyecto)
define('LOGIN_BG_IMG', 'img/login/bg-default.jpg');
```

### 3. Agregar override CSS en `custom.min.css`
**Archivo:** `C:/xampp/htdocs/voley/plantilla/assets/css/custom.min.css`

Agregar al final:
```css
/* ---- Login background image ---- */
.auth-one-bg {
  background-image: url('../../img/login/bg-default.jpg') !important;
  background-position: center;
  background-size: cover;
}
```

Nota: La ruta `../../img/login/` es relativa a `plantilla/assets/css/` → sube 2 niveles hasta `voley/` y entra a `img/login/`.

### 4. Reemplazar la imagen en el PHP con la constante (opcional pero recomendado)
**Archivo:** `C:/xampp/htdocs/voley/modulos/sesion/iniciar_sesion.php`

Línea 45, cambiar de:
```php
<div class="auth-one-bg-position auth-one-bg" id="auth-particles">
```
Se mantiene igual, pero el CSS ahora lee la constante. Para que sea dinámico, agregar un `<style>` inline en el `<head>`:

```php
<style>
  .auth-one-bg {
    background-image: url('<?php echo WEB_ROOT . LOGIN_BG_IMG ?>') !important;
  }
</style>
```

Esto elimina la dependencia de la ruta hardcoded en el CSS y permite cambiar solo la constante.

### 5. Actualizar `custom.min.css` para que NO hardcodee la ruta (ya que PHP la inyecta)
**Archivo:** `C:/xampp/htdocs/voley/plantilla/assets/css/custom.min.css`

Eliminar o comentar el bloque `.auth-one-bg { background-image: ... }` para que el estilo solo venga del inline de PHP (paso 4). Esto evita tener la ruta duplicada.

### 6. Probar
1. Abrir `http://localhost/voley/` en el navegador
2. Verificar que el login muestra la imagen de fondo (`bg-default.jpg`)
3. Cambiar la imagen: copiar una nueva a `img/login/mi-imagen.jpg`
4. Editar `configuracion.php` → `define('LOGIN_BG_IMG', 'img/login/mi-imagen.jpg');`
5. Recargar el login y verificar que muestra la nueva imagen

## Tests / validation

Para cada paso:
1. `mkdir` → verificar con `ls img/login/` que existe el directorio y el placeholder
2. `define` en configuracion.php → verificar que no rompe la carga (la home sigue funcionando)
3. CSS override → inspeccionar en DevTools (F12) que `.auth-one-bg` tiene el `background-image` apuntando a `img/login/bg-default.jpg`
4. Inline style → inspeccionar el `<head>` y verificar que aparece el `<style>` con la ruta correcta
5. Prueba manual de cambio:
   ```bash
   cp /ruta/a/nueva-foto.jpg "C:/xampp/htdocs/voley/img/login/test-bg.jpg"
   ```
   Cambiar temporalmente la constante, recargar, verificar, volver a la original

## Risks, tradeoffs, y open questions

- **Riesgo:** El `!important` en CSS puede conflictuar con el gradiente de `.bg-overlay`. Verificar que el overlay (oscurecimiento) siga funcionando sobre la nueva imagen.
- **Tradeoff:** Poner la ruta en `configuracion.php` (PHP) vs. solo reemplazar el archivo. La constante permite cambiar sin FTP, solo editando un archivo de texto.
- **Open question:** ¿El usuario quiere poder cambiar la imagen desde un panel de administración (base de datos) o es suficiente con editar un archivo? Por ahora se asume "archivo de configuración" por simplicidad.
- **Open question:** ¿La partículas/animación del div `#auth-particles` debe persistir? Se mantiene, solo cambia la imagen de fondo.
